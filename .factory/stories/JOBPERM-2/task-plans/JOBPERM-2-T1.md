# JOBPERM-2-T1 — Once grants end to end

Contract (AC1–AC4 of `plans/active/JOBPERM-2-job-permissions-one-card-path-with-rule-once-grants.md`): every permission request a scheduled-job run raises attaches to the job permission card; a request with no persistable rule becomes a `once` need row; Allow on a once row replays a signed `allow_once` (no rule written) and the held tool call resumes; Deny denies; `rule` rows unchanged and rows without a stored mode read as `rule`; an attach failure denies the tool call with a logged plain reason — never the classic chat prompt; the job-only cancel-only option rewrite is deleted. Buttons stay exactly Allow / Deny; provider renderers, runner, heartbeat, schema untouched.

Steps:
1. `apps/core/src/app/bootstrap/job-permission-durability-wiring.ts` `attachRequest` (line ~212): stop returning `false` when `persistentRules(request)` is empty. Derive `grant: 'rule' | 'once'` (`once` = no persistable rule). A `once` need uses the request id as its identity and carries no grant atoms; a `rule` need is exactly today's canonical-rule need. Carry `grant` through `job-permission-durability.ts` (need/effect contracts) and `domain/ports/job-permission-durability.ts` (persisted need/revision-row shape, optional field; absent ⇒ `rule` on read). No schema migration (JSONB record, A-0065).
2. Row copy: `apps/core/src/domain/job-permission-card-actions.ts` renders a once row from the sanitized request summary as "<tool>: <command> (this run only)"; `job-permission-card-projection.ts` keeps the grant on the row and lets atom paging tolerate an empty once scope. Actions unchanged (exactly Allow / Deny); `job-permission-provider-actions.ts` Allow transition preserves once mode.
3. Settlement: `job-permission-reconciler.ts` apply/handoff guards (~`:330`, `:341`) must not treat an empty atom set as nothing-to-apply. On Allow both modes re-run the deterministic rails; only `rule` writes rules. A once Allow replays a signed `allow_once` decision (`decidedBy: human_once`, no `updatedPermissions`) to the waiting runner via the existing replay path (the runner already verifies signed allow_once, `adapters/llm/anthropic-claude-agent/runner/permission-callback.ts:329`). Deny unchanged.
4. IPC: `apps/core/src/runtime/ipc-interaction-processing.ts` job branch (~`:205`): call `attachRequest` for every `request.jobId`; if it returns false or throws, deny the tool call with reason "Could not raise the job permission card: <cause>" and log one WARN line — never `deps.requestPermissionApproval`. Delete the `if (input.hostJobId)` decision-option rewrite in `apps/core/src/runtime/ipc-permission-classifier-decision.ts` (~`:436–440`) and any now-dead helper it alone used.
5. Tests (implementer writes): `apps/core/test/unit/application/jobperm-durability.test.ts` — `it('attaches a job request with no persistable rule as a once need')` (required test, exact leaf name), once Allow replays signed allow_once and writes no rule, absent grant reads as rule; `jobperm-ask-and-wait.test.ts` — `jobperm-1-t1-card-not-cancel` moves off the removed option shape, IPC attach failure denies with reason and no classic prompt; `jobperm-edges.test.ts` — provider-card contract: once row copy, Allow/Deny only. Update any `apps/core/test/unit/runtime/` expectation that pinned the cancel-only rewrite.
