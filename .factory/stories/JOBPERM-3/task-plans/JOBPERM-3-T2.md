# JOBPERM-3-T2 — Slack + Discord delete and Teams receipt card for retired cards

Context: T1 (commit f8cc8c4bd) made a retired job permission card revision carry `retireOutcome` ('allowed' | 'expired'), `retiredRows` and `retireDelivery`; the wiring (`apps/core/src/app/bootstrap/job-permission-wiring-setup.ts:391`) already delivers retire/allowed with `MessageSendOptions.deleteMessageId` and every other retire with `replaceMessageId` + the receipt text. Only Telegram acts on it. On Slack and Discord an allowed retire currently falls through to a NEW generic message (the old card stays); on Teams zero-action retire/replace messages fall through to `sendTeamsTextMessage` and neither `replaceMessageId` nor `deleteMessageId` is handled. T2 closes AC1 for the remaining providers and AC4.

Contract (JOBPERM-3-T2-AC1, -AC2, -AC4 as recorded): Slack and Discord delete a fully allowed card and fall back to a receipt edit when the delete fails; Teams edits the card to a one-line approved receipt card (no buttons) or sends the receipt when no activity id is recorded; expired retire revisions reach all three as the per-row 'Expired: <command>' edit, never a delete; all three return `jobPermissionCardRetireDelivery` so the reconciler records `deletedAt` / `receiptMessageId` / `deleteFailedAt`; a retried retire revision with a recorded marker makes NO provider call. Existing suites pass; tsc and architecture green.

Steps:
1. Shared settlement helper (`apps/core/src/channels/job-permission-card-settlement.ts`, new): hoist Telegram's per-message lane + persisted-marker short-circuit from `apps/core/src/channels/telegram/job-permission-card-delivery.ts:81` (`JobPermissionCardDeliverySettlement`: serialize same-message operations; if `revision.retireDelivery.deletedAt` or `.receiptMessageId` is set return that payload without any call; run `deleteFn`, on failure persist `deleteFailedAt` then `receiptFn`). Telegram switches to the helper with no behaviour change (its tests stay green unchanged).
2. Slack (`apps/core/src/channels/slack/channel-delivery.ts:104`): before the `replaceMessageId` branch, handle `options.deleteMessageId` through the helper — `chat.delete({ channel, ts })`, fallback `chat.update` with the receipt text and empty blocks; use the bounded rate-limit retry from `channel-delivery-helpers.ts:68` for both calls. Expired retire keeps `chat.update` (replace path). Return `jobPermissionCardRetireDelivery`.
3. Discord (`apps/core/src/channels/discord/index.ts:184`): same shape via the shared mutation requester in `http-helpers.ts:67/164` (DELETE message, fallback PATCH with receipt content and no components). Never the CHAT path's raw fetch.
4. Teams (`apps/core/src/channels/teams/progress.ts:44` + `interaction-handlers.ts:423` pattern): a retire revision with `replaceMessageId`/`deleteMessageId` and a recorded activity id → `updateAdaptiveCard` with a buttonless receipt card (allowed: "Approved — this job's permission requests are done."; expired: one 'Expired: <command>' line per row); no activity id or update failure → send a plain receipt text (existing fallback). Return `{ receiptMessageId }`. No delete support is added (the `TeamsSdkClient` has no delete; ceiling is the receipt card — plan Risks).
5. Types: if a provider needs it, extend `MessageDeliveryResult.jobPermissionCardRetireDelivery` (`apps/core/src/domain/types.ts:601`) only with fields Telegram already uses; no new shapes.

Tests (implementer writes): `apps/core/test/unit/channels/slack.test.ts` — `it('deletes a fully allowed job permission card and falls back to a receipt edit')` (required leaf), expired retire edits and never deletes, retried retire with `deletedAt` makes no call; `apps/core/test/unit/channels/discord/discord.test.ts` — same required leaf name + the two siblings using the existing `globalThis.fetch`/`jsonResponse` fixture; `apps/core/test/unit/channels/teams/teams.test.ts` — `it('edits a fully allowed job permission card to a receipt card')` (required leaf) + no-activity-id fallback using the injected `TeamsSdkClient` fake (`teams-card-1`); `apps/core/test/unit/channels/telegram.test.ts` unchanged and green.
