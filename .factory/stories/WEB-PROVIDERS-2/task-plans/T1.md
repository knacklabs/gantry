# T1 — Registry metadata and browser reactivation contract

## Objective

Expose the existing registry’s safe credential metadata and let only the browser facade reactivate a disabled same-mode credential after validating its merged stored payload. Bearer Control API and CLI behavior remain unchanged.

## Contract

- Add optional registry `multiline` metadata and mark only Vertex service-account JSON.
- Forward that metadata in the existing sanitized list DTO; credential values remain write-only.
- Add an opt-in `reactivateDisabled` rotation path. It merges stored and supplied fields, validates the complete result before upsert, and leaves invalid disabled records untouched.
- Set that option only from the existing browser PATCH route. Leave all other callers unchanged.
- Correct the configuration-check messages to describe Gantry-side credential resolution and projection only.

## Proof

- Registry unit coverage iterates every executable provider/mode and checks safe metadata without secret values.
- Credential-service coverage proves opt-in reactivation, sparse merge, failed-validation atomicity, and default disabled rejection.
- Browser-facade route coverage asserts its opt-in call and local-only copy.
