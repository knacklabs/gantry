## Gaps for scaling out

From **area 11**, distinguished from additional architecture work:

- **Secret configuration:** background payload encryption lacks the credentials path’s file-backed resolver. All three container roles need consistent key resolution and rotation.
- **Provider budgets:** separate gateways already exceed a shared cap within one process; split processes additionally lack deployment-wide admission accounting. Embeddings omit configured limits.
- **Readiness:** split workers have registration/scheduler checks that hosted `all` omits. Derive checks from enabled subsystems consistently.
- **Inline versus worker execution:** scheduled permission handling remains different, assigned to existing permission plans.
- **Host/runner transport:** local-folder IPC requires co-location or an explicit shared-filesystem/remote-transport contract for separately placed runners; assigned to MSG-4.
- **Credential setup:** the binding sweep creates nothing. It supplies no additional startup guarantee in either deployment shape.
- The unsafe Linux launcher matters to host operation, **not specifically container scaling**.

## Covered by existing plans

The reports assign **PERMFLOW-1–4** permission gates, command interpretation, scheduled execution and setup/cards; **MSG-1–4** ingress persistence, delivery/retries, interaction state and transport; **UX-1** forms, reviews and progress; **PROV-1–4** native provider streaming; **TURN-1/T8** durable retries/commit; and the **Stop-button deletion** its callbacks/tests. These are scope assignments, not completion claims; several referenced plan documents are absent here.
