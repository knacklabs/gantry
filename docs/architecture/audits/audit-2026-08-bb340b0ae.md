# External Security & Architecture Audit — 2026-08

**Audited snapshot:** commit `bb340b0aedde1d74e12ea5e821326488fea4cac4` (main).
Current main is ahead; every finding requires a currency check before paydown.

**Overall risk:** High. No Critical accepted; 5 High, 6 Medium, 1 Low confirmed.
Theme: individually sound controls do not form one end-to-end ownership boundary —
fleet and persistence capabilities advanced faster than their ownership models.

## Five highest-priority findings

1. **[High] Browser source-based upload trusts the whole worker temp dir.**
   `allowedAttachRoots()` (runtime/browser-file-attach-source.ts) permits `realpath(os.tmpdir())`;
   path-backed `browser_act` file_upload/file_attach bypass FileArtifactStore app/agent scoping;
   a unit test uploads from an arbitrary sibling temp dir and asserts Playwright receives it.
   Cross-run/cross-agent/cross-app file disclosure. Fix: drop tmpdir root; require a scoped
   FileArtifactId or a per-run 0700 staging dir whose ownership is in the signed IPC context.

2. **[High] LLM/API rate + concurrency limits are process-local while fleet scaling shipped.**
   Each worker owns its own GatewayRateLimiter; control routes/llm.ts uses module-local
   in-flight counters; control/rate-limit.ts is a process-local Map. Decision 0099 requires a
   Postgres-backed cluster authority before fleets — its revisit trigger has fired. Effective
   limit becomes instance-count multiple (≈6R with 6 workers). Fix: one cluster-authoritative
   admission store (atomic weighted windows + durable concurrency permits) or a singleton
   admission service made an explicit availability boundary.

3. **[High] Browser profile snapshot/restore fully buffer unbounded state.**
   collectUserDataFiles reads every file with no byte/count/depth budget; serial per-file
   PutObject; restore downloads all bodies before validating. Worker OOM / long finalization.
   Fix: hard budgets (total bytes, single-file, count, depth, restore bytes) preflighted on
   metadata; streaming deterministic archive + manifest.

4. **[High] Browser profile versions retained indefinitely.**
   Content-addressed prefixes with a pointer-only table; no deletion/retention/version-listing;
   stale-upsert leaves the just-uploaded prefix orphaned. Snapshots hold Chrome Login Data /
   Local State key material. Fix: lifecycle — record recent versions, GC superseded after a
   bounded rollback window, delete stale uploads, app/agent/conversation deletion, consider
   envelope encryption.

5. **[High] Outbound webhook HMAC secrets stored plaintext in Postgres.**
   `control_http_webhooks.secret` plain text; register/update write raw; delivery reads raw —
   while the adjacent external-ingress repository already encrypts its secrets. Read-only DB
   access discloses every signing key. Fix: encrypted runtime-secret envelope bound to
   appId+webhookId, decrypt only at the signing boundary, key rotation, migrate rows.
   Related Medium: server-generated `randomUUID` secret is never returned in the 201, so the
   webhook cannot be verified by the caller.

## Medium

- **Server-generated webhook secret never returned** (routes/webhooks.ts) — return once at create.
- **Every job worker runs full scheduler sync + maintenance** (pgboss/scheduler-engine.ts
  syncAllJobs + per-minute timer; jobs/cleanup.ts getAllJobs + per-row delete) — no leader
  election; W×N amplification. Fix: elect one scheduler/maintenance coordinator via existing
  lease; set-based SQL cleanup.
- **Session-feed JID compatibility does a text→jsonb scan with no expression index**
  (sessions/session-interaction-module.ts, domain-repositories listConversationIdsForJid) +
  N-way child-query fan-out. Fix: partial expression index now; finish canonical restamp.
- **Browser snapshot publication failures swallowed without durable retry**
  (live-turn-browser-finalizer.ts, execution-browser-cleanup.ts) — misleading success, lost
  state. Fix: durable pending-publication/outbox keyed by profile+fencing.
- **Integrity failure can launch/republish older local browser credential state**
  (browser-profile-sync.ts fail-open; test asserts the unsafe behavior) — state rollback with
  increasing fence number. Fix: quarantine/clear local profile on integrity failure; never
  publish a profile derived from an unverified base.
- **Runtime events have no shipped retention owner** (schema/events.ts, 9 indexes; decision
  0013 defers to operator job never implemented) — unbounded sensitive retention. Fix: own
  retention at the Runtime Event Exchange, protect pending outbox/webhook rows, partition later.

## Low

- **main fails its own architecture gate at the snapshot** — stale active-doc reference

## Strongest simplifications

1. **Delete the no-op credential-binding setup/cache/retry machinery** — both production
   binding functions (agent-credential-service.ts) intentionally return undefined while
   runtime-app.ts/startup.ts maintain caches, loops, timeouts, tests.
2. **Finish canonical conversation restamp; delete the JID compatibility fan-out.**
3. **Elect one scheduler/maintenance authority; keep workers as pure consumers.**
4. **Stream browser profiles as one deterministic bounded artifact.**
5. **Thin the composition roots / Postgres god-modules by existing role+domain boundaries.**

## Rejected hypotheses (do NOT re-open)

Cross-app session/run access; outbound webhook SSRF; external-ingress signature/replay bypass;
browser-profile provider-account isolation; SSE stream leak; public-feed lost messages; normal
browser upload traversal; simple-YAML quote corruption (stale TODO); empty packages/agent-runner
(git can't track empty dirs); self-hosted CI secret persistence (disposable runner);
seccomp=unconfined (pre-prod hardening gate, not a proven exploit).

## Recommended execution order

1. Blockers: browser upload ownership · encrypt webhook secrets + fix create contract ·
   browser profile resource budgets · remove unsafe integrity fail-open · durable snapshot
   publication · decide cluster-wide rate authority (supersede 0099).
2. Performance: one scheduler/maintenance coordinator · set-based cleanup · conversation JID
   expression index · Runtime Event Exchange retention.
3. Simplifications: delete credential-binding machinery · fix arch-doc reference.
4. Larger refactors (separate plans): streamed profile artifact · canonical restamp ·
   scheduler authority split · thin composition roots.
