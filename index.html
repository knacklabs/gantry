The runtime between AI intent and real-world action.

Gantry is a self-hosted, provider-neutral agent runtime. It accepts work from chat, applications, schedules, and signed ingress; applies memory, policy, permissions, sandboxing, and credential isolation; then records the complete result in durable runtime state.

Interactive turn

How one message becomes a governed run.

The same execution spine serves provider chat, SDK sessions, and application work.

01NormalizeProvider payload becomes canonical app, conversation, thread and sender identity.
02PersistThe message is durable before model execution is admitted.
03ClaimQueue capacity and Postgres lease fencing serialize the live scope.
04ComposeCurrent agent config, memory, session continuity and capabilities are loaded.
05ExecuteThe compatible model harness starts or resumes a provider session.
06AuthorizeEach risky tool call is allowed, reviewed, or denied by host policy.
07DeliverText streams out; final answer, usage, events and receipts become durable.

Security model

Authority stays in the host.

Model output, providers, browser backends, MCP servers, tools and worker processes are treated as untrusted execution surfaces.

Identity

Who is asking?

App ownership, sender policy, conversation membership and control approvers are checked independently.

Authority

What may run?

Only selected, versioned capabilities and current granular rules can authorize an action.

Containment

Where can it run?

Enforcing sandbox providers, protected paths, egress policy and bounded IPC constrain execution.

Secrets

Which credential lane?

Model tokens stay behind the loopback gateway. Tool credentials use separate reviewed capability bindings.

Deployment

One process locally, split roles in a fleet.

Role capabilities are data-driven and fail closed. Worker roles mount only operations routes.
