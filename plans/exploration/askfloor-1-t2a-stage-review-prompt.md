## Workflow
What moves through this task: one permission request for an MCP tool call or a shell command, from the IPC request through the deterministic rails to a verdict, and one classifier consultation from its branches to a typed result. This task starts at the rails' birthright tables and the read gate's inputs and stops at the rails verdict and the classifier result; the IPC tail's merge, the memory stages and the outage latch are other tasks.

```mermaid
flowchart TD
  R[PermissionApprovalRequest] --> B{birthright tables}
  B -- input-independent row --> A1[ALLOW birthright]
  B -- input-gated row, no typed fact --> C{complete, unsanitized,\nunredacted input?}
  C -- no --> ASK1[ASK incomplete input]
  C -- yes --> A1
  B -- attachment_open --> P{typed pre-sanitization fact\nattachmentOpenIds.wellFormed?}
  P -- absent or false --> ASK1
  P -- true --> A2[ALLOW birthright attachment_open]
  B -- no row --> G[read gate]
  G --> S[effect shape: pure\nshape, action, targets, requiresTarget]
  S --> H[hard boundaries: capability,\nrealpath, protected, hidden, secret]
  H --> V[rails verdict unchanged]
  V --> K[classifier consult]
  K --> N[native-risk helper -> skipped]
  K --> D[strict / skipped-local -> skipped]
  K --> L{LLM}
  L -- verdict --> ANS[status answered]
```
