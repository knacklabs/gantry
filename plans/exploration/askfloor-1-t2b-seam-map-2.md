## Answers (Codex gpt-5.6-terra @ high, read-only, 2026-09-05)

1. `low` and `medium` both produce classifier `allow`; `high` (and `critical`) take the ask tail. `coordinatePermissionClassifierRisk` implements this directly. `apps/core/src/runtime/permission-decision-coordinator.ts:92-100`. IPC permits that allow unless a rail requires approval without permitted interactive-auto relaxation. `apps/core/src/runtime/ipc-permission-classifier-decision.ts:387-444`, `apps/core/src/runtime/ipc-permission-classifier-decision.ts:487-529`. Inline returns `allow_once` when the consult result is `allow`. `apps/core/src/app/bootstrap/inline-agent-loop-tools.ts:409-445`. Medium is therefore an allow in normal auto IPC and inline paths. Tests pin this at `apps/core/test/unit/runtime/permission-decision-coordinator.test.ts:162-180` and `apps/core/test/unit/runtime/ipc-permission-classifier-decision.test.ts:191-214`.

2. The auto-strict guard is `!deterministicGate?.allowed && input.permissionMode === 'auto_strict'`; it returns skipped/high/ask before `nativeRisk` is considered. `apps/core/src/runtime/permission-classifier.ts:348-364`. Gantry MCP tools receive no deterministic read-only proof in that gate. `apps/core/src/shared/auto-permission-read-only-gate.ts:137-148`. Thus a native-map-low `mcp__gantry__browser_status` does not allow through this helper in `auto_strict`; it receives the high strict result. Browser status is low in the native map. `apps/core/src/application/permissions/gantry-tool-risk.ts:146-158`, `apps/core/test/unit/application/gantry-tool-risk.test.ts:48-67`. The strict-map test pins the same precedence for a Gantry mutation. `apps/core/test/unit/runtime/permission-classifier.test.ts:958-981`.

3. IPC only calls the consult when lane is `interactive_auto` or `auto_strict`, runtime-event publishing exists, and classifier config exists. `apps/core/src/runtime/ipc-permission-classifier-decision.ts:325-383`. `hostJobId` derives `autonomous`, and ask mode derives `ask`; neither meets that condition. `apps/core/src/application/permissions/auto-lane-analysis.ts:97-114`. Inline invokes the consult whenever `publishRuntimeEvent` exists after its coordinator tail is reached; ask mode then returns from the consult's mode gate before native risk, while an inline scheduled job in auto mode can call it. `apps/core/src/app/bootstrap/inline-agent-loop-tools.ts:389-445`, `apps/core/src/runtime/permission-classifier.ts:253-265`.

   - Any namespaced but unknown Gantry suffix is high; non-Gantry names return `undefined`. `apps/core/src/application/permissions/gantry-tool-risk.ts:101-107`.

MCP server registration is distributed among tool registrars. `apps/core/src/runner/mcp/server.ts:120-133`.

5. `browser_act` uses discriminator `action`; its payload is the generic object under `payload`. `file_upload` and `file_attach` are action values. `apps/core/src/runner/mcp/tools/browser.ts:204-225`, `apps/core/src/runner/mcp/tools/browser.ts:304-333`. The artifact policy accepts one of `source`, `files`, or `paths`; `source.type` supports `bytes`, `path`, and `artifact`, while `path` accepts `path` or `paths`. `apps/core/src/adapters/browser/browser-artifact-policy.ts:47-100`, `apps/core/src/adapters/browser/browser-artifact-policy.ts:103-153`. Direct `file_upload.paths` is rejected, but `source: { type: "path", path|paths }` is normalized before that test and then resolved through the attach-path branch. `apps/core/src/adapters/browser/browser-artifact-policy.ts:57-98`.

   On the IPC path, `classifierToolInput` is a sanitized object copy of the original decision input, using the classifier string limit; it is not a serialized string. `apps/core/src/runtime/ipc-parsing.ts:433-454`, `apps/core/src/runtime/ipc-parsing.ts:491-498`. The consult receives that classifier copy preferentially. `apps/core/src/runtime/ipc-permission-classifier-decision.ts:367-370`.

6. Anthropic's SDK callback receives native tool name and input. `apps/core/src/adapters/llm/anthropic-claude-agent/runner/query-loop-phases-setup.ts:479-495`. Its permission request maps native `Edit` to `FileEdit` and `Write` to `FileWrite`; the host classifier eligibility gate therefore receives `FileEdit`/`FileWrite`, which are ineligible provider-native facade names. `apps/core/src/shared/gantry-tool-facades.ts:64-76`, `apps/core/test/unit/application/permission-classifier.test.ts:29-36`.

   Anthropic preserves native input `{ file_path, patch }` or `{ file_path, content }` into the permission request. `apps/core/src/adapters/llm/anthropic-claude-agent/runner/tool-permission-gate.ts:621-674`. DeepAgents maps facade calls to native-shaped `Edit`/`Write` only for its local policy request, but writes the facade name and original input to IPC: `FileEdit` with `{ path, patch }`, `FileWrite` with `{ path, content }`. `apps/core/src/adapters/llm/deepagents-langchain/runner/gantry-facade-tools.ts:110-132`, `apps/core/src/adapters/llm/deepagents-langchain/runner/gantry-facade-tools.ts:160-189`.

   `PermissionApprovalRequest` has no `workspaceRoot`, `cwd`, or trusted-roots field. `apps/core/src/domain/types.ts:179-241`. IPC derives workspace root from the source folder, passes it to classifier input, and passes settings trusted roots to deterministic rails. `apps/core/src/runtime/ipc-permission-classifier-decision.ts:82-118`, `apps/core/src/runtime/ipc-permission-classifier-decision.ts:131-135`, `apps/core/src/runtime/ipc-permission-classifier-decision.ts:367-375`.

7. `resolveWritableWorkspacePath(relativePath, config, toolName)` is async and returns `Promise<string>`. `apps/core/src/adapters/llm/deepagents-langchain/runner/gantry-facade-file-safety.ts:39-43`. It realpaths the workspace root, uses `lstat`, `realpath`, and may create missing parent directories for `FileWrite`; it rejects lexical escape, symlink path components and target symlinks, requires existing edit targets, and returns a missing write target. `apps/core/src/adapters/llm/deepagents-langchain/runner/gantry-facade-file-safety.ts:44-67`, `apps/core/src/adapters/llm/deepagents-langchain/runner/gantry-facade-file-safety.ts:88-132`. It requires a config object rather than a workspace-root string and is filesystem-touching, so it is not pure or reusable as a pure application helper without a wrapper.

8. List responds through `acceptData` with `{ ok: true, artifacts }`; each descriptor has `id`, `scope`, `path`, `version`, `contentHash`, `sizeBytes`, `contentType`, `createdAt`, optional `createdBy`, and optional `promotedFromArtifactId`. `apps/core/src/jobs/ipc-file-artifact-handlers.ts:109-121`, `apps/core/src/domain/file-artifacts/file-artifact.ts:26-37`, `apps/core/src/domain/file-artifacts/file-artifact.ts:58-74`. Read responds with `{ ok: true, artifact, content }`; content is UTF-8 `{ encoding, text, offset, bytesReturned, totalBytes, truncated }` or base64 `{ encoding, data, offset, bytesReturned, totalBytes, truncated }`. `apps/core/src/jobs/ipc-file-artifact-handlers.ts:124-159`, `apps/core/src/jobs/ipc-file-artifact-handlers.ts:341-360`.

   Handler failures call `reject(error, code)` and the outer catch converts thrown operation errors to `reject(..., "invalid_request")`; they are not returned as `{ ok: false, error }` from the handler. `apps/core/src/jobs/ipc-file-artifact-handlers.ts:228-233`, `apps/core/src/jobs/ipc-shared.ts:140-153`. The handler test has one suite, `file artifact IPC handlers`; it contains read tests but no list-specific test or describe title. `apps/core/test/unit/jobs/ipc-file-artifact-handlers.test.ts:113-114`, `apps/core/test/unit/jobs/ipc-file-artifact-handlers.test.ts:160-261`.
