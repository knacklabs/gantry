# Family-grant neutrality gap hunt (read-only, no edits, keep reading TIGHT)

The CARDSIMPLE-1 family-grant implementation (branch feat/CARDSIMPLE-1-family-wide-grants, commit 15b87e9ff — review the CURRENT checkout) is meant to be COMMAND-NEUTRAL: one Allow on any eligible simple command records `RunCommand(<literal argv0> *)` so future invocations of that argv0 with different arguments proceed without asking. `curl` was only the owner's example. Hunt for gaps where the behavior is NOT neutral or NOT complete across command types and entry surfaces.

Ground truth to audit: `shared/family-rule-synthesis.ts` (synthesizer + predicate + isFamilyRunCommandRule), `shared/durable-access-policy.ts` (validator amendment), `shared/tool-execution-policy-service.ts` (isFamilyRule marking), `runtime/permission-decision-coordinator.ts` (rails-before-family), the three minting lanes (`application/permissions/permission-suggestion-synthesis.ts`, `adapters/llm/anthropic-claude-agent/runner/permission-suggestions.ts`, `shared/autonomous-bash-recovery-rule.ts`), and `app/bootstrap/inline-agent-loop-tools.ts`.

Any evaluator that still compares exact-argv and would re-ask despite a stored family?
