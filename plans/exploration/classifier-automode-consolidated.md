# Auto-mode-parity for gantry permissions — consolidated findings & change set (2026-09-01)

Owner ask: make gantry agent permissions behave like Claude Code auto mode — the classifier judges unknown actions on their own risk, auto-allows the harmless ones, asks ONLY genuine risk, and LEARNS human decisions so they aren't re-asked. Codex sol@xhigh ran 3 scoped passes (classifier-gaps-1/2/3); combined with host findings below.

## The three structural gaps (root causes)

G1. **Identity-based force-ask skips the classifier.** `gantryToolDefaultRisk` (gantry-tool-risk.ts:105-166) returns HIGH by TOOL IDENTITY for ~9 buckets (authority-changing, unscoped-dispatcher, delegation, decision-actor, destructive-verb, arg-dependent `file`, scheduler mutations, `send_message`, non-read admin, mutating `browser_*`, unknown/unmapped fallback). Any HIGH ⇒ ask, and the LLM classifier at permission-classifier.ts:354-383 never runs. Several conflate "what tool" with "how risky THIS call is" — a browser navigation, a send to an already-approved destination, an approved-job pause, a grantable-exact mutation all ask needlessly. `grantable-exact` (MEDIUM) is shadowed by the earlier HIGH checks. CONFIRMED GOOD: shell commands (no static bucket) DO reach the LLM and auto-allow at low/medium; only truncated-input, YOLO denylist, and auto_strict-without-read-only-proof force HIGH deliberately.

G2. **Human decisions are not learned — only hinted.** A human Allow becomes prompt-hint text (permission-classifier.ts:368 via promotion counters); the verdict still comes fresh from the classifier's risk_level (:377-383). The effect hash (permission-effect-key.ts) caches CLASSIFIER verdicts, not human outcomes. So an identical request can ask again. Key mis-scoping: promotion history keys on the FAMILY rule (over-collides different args), the verdict hash keys on raw command+cwd+churny fields (under-collides real repeats). Ungrantable shapes (shims/pipes) have NO learning path ⇒ re-ask every run (the scheduled-job q2h pain).

G3. **Runner shims can't hold ANY durable grant.** npx/uvx/pnpx + npm exec/pnpm dlx/yarn dlx/bun x get no family (family-rule-synthesis.ts runnerShimBashLeafReason) ⇒ re-ask forever. Host findings 1-5 (in cardsimple-2 plan) + the live stale-card incident stem from this class.

## Recommended change set (ordered by UX impact)

1. **Learn human decisions by exact effect-hash (ASKFLOOR-1, highest impact).** Record a human settlement keyed by the exact effect hash; consult it BEFORE the LLM; auto-allow an identical request the human already allowed. Invalidate on rails-version bump (a tightened rule re-asks). Bounded to auto mode. Use exact effect hash for LEARNED authority; keep family keys promotion-hint-only. This is the piece that turns "asks every time" into "asks once" — covers shims/pipes too, which can never get a family grant.
2. **Argument-aware risk before the coarse identity buckets (ASKFLOOR-1).** Route coarse/unmapped gantry-native cases to the arg-aware classifier instead of unconditional HIGH: browser_act args (navigation/non-mutating ⇒ lower), send_message to already-approved destination, approved-job scheduler pause/resume/update, grantable-exact admin/mutations. Keep genuinely-inherent HIGH (delete/revoke/purge, authority-changing, unknown-namespaced) asking. Let a validated exact grant override only its relevant coarse bucket.
3. **Package-pinned shim families (new small story — the remotion fix). GO, conditional.** Grant `npx <pkg> *` (pinned to one package, open on args) — same safety class as `git *`. Requires: (a) recognize the pinned-runner shape before the generic `<exe> *` family check; (b) one shared argv extractor returning the literal package identity for npx/uvx/pnpx and after npm exec/pnpm dlx/yarn dlx/bun x, permitting only valueless flags like -y, rejecting -p/--package and unknown/value flags; (c) relax runnerShimBashLeafReason only when the extractor succeeds; (d) CRITICAL — pass the matched rule to runnerShimFamilyBypassReason and suppress bypass only when the pinned package EXACTLY equals the command's extracted package (without this signature change it's NO-GO). Reject list: bare `npx *`, `npx --package=x <pkg>`, `npx github:owner/repo`, `npx ./local`, `npx http://…`; allow `npx -y <pkg>` (single literal pkg) and `npx @scope/pkg` (strict literal registry grammar).
4. **Classifier-unavailable fallback (new story).** The await in permission-classifier.ts has no local fallback if the classifier is unavailable — define + test the degraded behavior (fail-closed to ask, explicitly).
5. **Card legibility (CARDSIMPLE-2, already folded).** Explain-on-exclusion, settle/retract lifecycle, compound-scope disclosure, retry-on-non-paused-job, ready-run-start clears stale setup_state.

## Sequencing
ASKFLOOR-1 absorbs #1+#2 (its "judge actually judges" charter fits both). #3 is a small standalone story (SHIMPIN-1?) that unblocks scheduled-job shim re-asks. #4 small. #5 is CARDSIMPLE-2. Net: after #1+#2, harmless actions stop asking and human decisions stick; after #3, remotion-class jobs stop re-asking; #5 makes the surface honest.
